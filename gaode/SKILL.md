# 周边去哪儿：基于高德的地点推荐助手

## 1. 适用场景

用户给出一句话需求，通常包含：城市、起点（评测环境会直接给出起点经纬度，无需自行定位）、要去的场所类型或关键词，以及可选的约束条件（步行时间上限、推荐数量上限、排序偏好、距离偏好、价格/时段等）。

示例：「我在杭州某地铁站，想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。」

本 Skill 的职责是一次单轮任务：理解需求 → 用高德查询真实地点 → 用高德查询步行路线 → 按条件筛选排序 → 用固定格式作答。不编造地点、地址、距离、时间。

## 2. 第一步：解析需求

从用户输入中提取并确认（缺失项用默认值，并在回答末尾简短说明所用默认值）：

| 槽位 | 说明 | 缺省处理 |
| --- | --- | --- |
| 起点 | 优先使用输入中给出的经纬度或地点名 | 若无坐标但有地点名，先用地理编码/关键词检索确定坐标；仍无法确定则向用户确认，不要猜测 |
| 城市 | 用于限定检索范围 | 取起点所在城市 |
| 目标类型 / 关键词 | 如「咖啡馆」「餐厅」「公园」「书店」 | 直接使用用户的原始词语作为检索关键词 |
| 步行时间上限 | 单位分钟，刚性条件 | 未给出时默认 15 分钟 |
| 推荐数量上限 | 刚性条件，且不超过 3 | 未给出时默认 3，且最多 3 |
| 偏好 | 如「优先近一点」「安静」「适合带孩子」 | 「优先近一点」→ 按步行时间升序；其他偏好只在与数据相关时体现 |

把「必须满足」的条件（类型、步行时间上限、数量上限）与「尽量满足」的偏好区分开：前者不可放宽，后者用于排序与解释。

## 3. 第二步：查询候选地点

使用高德「周边搜索」能力（附近检索，参数为关键词、起点坐标、搜索半径），必要时配合「关键词搜索」（关键词 + 城市）。

- 坐标统一使用「经度,纬度」的字符串格式，与高德返回结果保持一致，不要自行换算或四舍五入到过低精度。
- 搜索半径按步行时间上限估算：半径 ≈ 步行时间上限（分钟）× 80 米，再乘 1.5 的绕路余量。例如 15 分钟 → 约 1800 米。半径仅用于召回候选，不能当作可达性结论。
- 关键词先宽后窄：先用用户的原始词语检索；若结果过少，再用同类词或更宽的类型词补充一次（如「咖啡」→「咖啡馆」「咖啡厅」）。
- 只采信工具返回的字段：名称、地址、类型、坐标、距离等。不要为了凑数而虚构或「补全」地点。

## 4. 第三步：查询步行路线

对候选地点逐一调用高德「步行路线规划」（参数为起点坐标、终点坐标），获取真实的步行距离（米）与预计耗时（秒/分钟）。

- 排序策略：先按工具返回的直线距离由近到远取前若干（建议取数量上限 + 3，最多 8 个）作为待验证集合，再对集合内每个地点查询步行路线，避免无谓调用。
- 筛选：仅保留步行耗时 ≤ 步行时间上限的地点。步行时间一律以路线规划返回值为准，禁止用直线距离除以步速替代，也禁止用直线距离冒充步行距离。
- 排序：用户说「优先近一点」或未给出偏好时，按步行耗时升序；若用户给出其他可量化偏好（如「少走路但不要太吵」），仍以步行耗时为主序，其余偏好只用于调整解释。
- 去重：同一地点（同名且坐标接近）只保留一条。

## 5. 第四步：组织回答

用列表或表格作答，最多 3 条，每条包含：

| 字段 | 要求 |
| --- | --- |
| 名称 | 高德返回的地点名称 |
| 地址 | 高德返回的地址原文 |
| 步行距离 | 路线规划返回的距离，带单位（米/公里） |
| 步行时间 | 路线规划返回的耗时，单位为分钟 |
| 推荐理由 | 一句话，必须由已获取的数据支撑（例如「步行 6 分钟即到，位于起点东南方向」），不得写入未查询到的属性 |

推荐理由只能引用已知数据：位置关系、步行时间、距离、类型、地址。对「安静程度、排队情况、营业状态、评分、人均价格」等未经查询的信息，标注「未核实」，不要当作推荐依据，也不要编造。

回答开头用一句话复述关键条件（目标类型、步行时间上限、数量上限、排序偏好），结尾用一句话给出下一步建议（如「如需更近的选择，可以把步行时间限制缩短到 10 分钟再试」）。

## 6. 异常与边界处理

- 候选不足：若符合条件的地点少于数量上限，就按实际数量返回，并说明「在步行 X 分钟范围内只找到 N 个符合条件的地点」，不要用超时或类型不符的地点凑数。
- 完全没有结果：如实说明未找到符合条件的地点，并给出可操作建议（放宽步行时间、扩大范围、换用同义词），不要返回空表格冒充成功。
- 条件矛盾：如「步行 5 分钟内找大型商场」确实没有结果，说明限制过严，并给出放宽后的可选方案。
- 工具报错或无返回：先重试一次（可缩小半径或更换关键词）；仍失败则向用户说明「高德服务暂时不可用/查询失败」，并说明哪一步失败，不要用记忆中的地点信息作答。
- 起点不明确：请用户补充起点名称或坐标，不得默认某个城市中心。
- 不做跨城市推断、不做多站行程串联：每个推荐都是从同一起点出发的独立备选。

## 7. 硬性约束

- 地点、路线数据必须来自高德工具的本次调用，禁止凭常识补全。
- 不得把步行时间上限之外的地点列为「符合条件的推荐」；若列出仅供用户参考，必须明确标注为「超出步行时间限制」并单列，且不计入推荐数量。
- 不在回答中输出任何 API Key、密钥或工具配置信息。
- 回答使用与用户相同的语言，简洁、可直接照着走。
