# 周报匠 · Qoder 开发记录

本项目的需求拆解、编码、调试与验证均在本 Qoder 会话中完成。下面按时间顺序记录关键环节，便于核对 Qoder 在项目中的作用。

## 1. 需求拆解

一句需求：**每周五要从散落的笔记和会议纪要里手工拼周报，重复且容易漏风险项，用 seekdb 做一个随手记 + 一键出周报的小工具。**

Qoder 把这句话拆成四条可验收的需求：

1. 随手记：一行一条，自动分成「完成 / 风险 / 计划」三类；
2. 找得回：能按关键词在历史笔记里检索，并支持按周过滤（中文分词）；
3. 出草稿：按周把三类笔记拼成周报，格式稳定；
4. 会记事：署名、语气这类偏好保存下来，下次生成自动复用。

技术选型由 Qoder 给出并说明理由：seekdb（题目要求至少使用一种指定技术）承担存储与全文检索；前端用原生 ESM 避免引入构建链，降低评审复现成本。

## 2. 技术方案与实现

| 环节 | Qoder 完成的工作 |
| --- | --- |
| 数据库 | 设计 `work_notes` / `user_prefs` / `report_history` 三张表；`work_notes` 建 `FULLTEXT ... WITH PARSER ik` 中文全文索引 |
| 后端 | 编写 Express API（写入去重、自动归类、全文检索、偏好读写、周报生成），使用 seekdb-js 连接与参数化 SQL |
| 归类规则 | 关键词规则表，按「完成 → 风险 → 计划」优先级匹配（先匹配完成，避免「修复…问题」被误判为风险） |
| 前端 | 单页 UI（粘贴区、本周笔记、检索结果、周报草稿、偏好栏），所有请求直连本地 API |
| 样例数据 | 两周 12 条示例笔记 + 偏好，`samples/seed.mjs` 通过 API 灌入，保证与手工操作走同一路径 |

## 3. 调试过程（真实发生的问题）

1. **seekdb-js 安装失败**：`npm install` 报 `Unsupported URL Type "workspace:": workspace:*`。定位为 seekdb-js 的可选 peer 依赖 `@seekdb/default-embed` 在镜像源上的版本发布有问题；本项目不使用 embedding function，改用 `npm install --legacy-peer-deps` 安装通过，运行说明中已注明原因。
2. **全文检索写法验证**：先写了一个探针脚本，在 seekdb 里建临时表 `probe_ft` 验证 `MATCH(content) AGAINST('周报')` + `week` 过滤可以命中并返回相关度，再把写法落到服务端。
3. **归类错位**：首轮生成周报时，「修复检索结果分页错位的问题，已回归并通过」被归到「风险」（命中了「问题」）。把规则顺序改为「完成 → 风险 → 计划」并把 upsert 从只更新正文改为同时更新归类，重新灌入后 完成 3 / 风险 2 / 计划 2 符合预期。
4. **截图与展示**：页面加了对 `?week=&q=&report=1` 的深链支持，便于用无头浏览器复现「已导入数据 + 已检索 + 已生成」的可视状态，供项目网站截图。

## 4. 验证结果

- `GET /api/health`：`seekdb-v1.3.0.0`，当前周 `2026-W44`，笔记 12 条
- 写入：新增 1 条「把周报归档接入了日程提醒，已上线」→ 12 ms 返回，列表立即刷新，标签「完成」
- 检索：`缓存` → 命中 1 条，seekdb 侧 2.2–29.7 ms
- 周报：`2026-W42` → 完成 3 / 风险 2 / 计划 2，落款「示例同学」（偏好记忆），并提示「上次生成于 2026-W42」

完整步骤见仓库 `qoder/README.md` 的「验证样例」，库内核对 SQL 附在同一节。
